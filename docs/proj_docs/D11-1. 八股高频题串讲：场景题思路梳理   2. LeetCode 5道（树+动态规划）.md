## 第一部分：八股高频场景题思路梳理
### 场景题通用答题方法论（四步拆解法）
面试遇到业务场景类算法题，不要上来就写代码，按四步梳理思路，既体现工程思维，又不容易漏边界：
1. **业务澄清**：先确认边界条件：数据量级、更新频率、精度要求、延迟要求、并发量，避免理解偏差。
2. **模型抽象**：把业务问题映射到经典算法模型，比如「排行榜」→ Top K 问题、「缓存淘汰」→ LRU 问题。
3. **方案选型**：从简单到复杂给出 2~3 种方案，对比时间/空间复杂度，说明选型依据，对应不同业务阶段。
4. **工程落地**：补充并发安全、性能瓶颈、异常边界、工业级实现（比如 Redis 对应实现），体现工程经验。

### 场景 1：TOP K 排行榜场景
#### 业务背景
商品销量榜、用户积分榜、热门话题榜、实时在线人数排行；支持元素动态更新，查询前 K 名。

#### 算法抽象
给定动态更新的 N 个元素，高效查询权重前 K 大的元素，支持增删改。

#### 常见方案对比
| 方案                    | 时间复杂度     | 空间复杂度 | 适用场景                               |
| ----------------------- | -------------- | ---------- | -------------------------------------- |
| 全量排序取前 K          | O(nlogn)       | O(n)       | 数据量小（万级以内）、更新少、批量计算 |
| 小顶堆维护 Top K        | O(nlogK)       | O(K)       | 数据量大（百万级）、一次遍历、查询少   |
| 有序结构（跳表/红黑树） | 增删查 O(logn) | O(n)       | 高频更新、实时查询，比如秒级排行榜     |

#### 面试答题思路
> 先澄清：数据量大概多少？更新频率是秒级还是分钟级？需要精确排行还是近似排行？
1. 如果是离线批量计算、万级数据，直接全量排序取前 K 即可，实现最简单。
2. 如果是百万级数据、一次性遍历查询，用大小为 K 的小顶堆，遍历所有元素，比堆顶大就入堆，最终堆里就是 Top K，时间 O(nlogK)，空间更优。
3. 如果是实时高频更新的排行榜，用跳表实现的有序集合，增删改都是 O(logn)，还支持范围查询；工业级落地直接用 Redis ZSet，就是跳表实现，生产环境最常用。

#### 避坑与追问点
- 热点倾斜：头部元素变化极小的时候，能不能优化？→ 冷热分离，热点数据单独维护。
- 大数据量：千万级以上全内存存不下怎么办？→ 分桶+归并，或者数据库索引+分页。
- 并列排名：相同分数怎么处理？→ 排名跳跃还是连续，确认业务规则。

### 场景 2：LRU 缓存淘汰场景
#### 业务背景
本地内存缓存、Redis 缓存淘汰策略；缓存容量有限，满的时候删除最久未使用的元素。

#### 算法抽象
固定容量的缓存，支持 O(1) 查询、O(1) 插入，容量满时淘汰最久未访问的元素。

#### 常见方案对比
| 方案            | 核心实现                               | 查询/插入复杂度 | 适用场景                 |
| --------------- | -------------------------------------- | --------------- | ------------------------ |
| 数组+时间戳     | 每次访问更新时间戳，淘汰时遍历找最小   | O(n)            | 极小容量、演示用         |
| 哈希表+双向链表 | 哈希表存节点引用，双向链表维护访问顺序 | O(1)            | 标准 LRU，工业级基础实现 |
| LFU/ARC         | 按访问频率淘汰/自适应淘汰              | O(1)            | 访问模式稳定的缓存场景   |

#### 面试答题思路
> 先澄清：缓存容量多大？读写比例？有没有特殊访问模式？
1. 标准 LRU 用「哈希表+双向链表」实现，哈希表负责 O(1) 查找，双向链表维护访问顺序，最近访问的放头部，淘汰从尾部删。
2. 访问节点的时候，要把节点移到链表头部，这一步是 O(1) 因为有哈希表直接定位节点，不用遍历。
3. 工程落地的话，还要考虑并发安全，本地缓存要加读写锁；分布式缓存直接用 Redis 的 allkeys-lru 策略。
4. 如果是热点集中在头部的场景，还可以优化成 LRU-K，避免单次冷数据冲掉热点。

#### 避坑与追问点
- 并发安全：多线程读写 LRU 怎么保证线程安全？→ 读写锁分段锁，或者用 ConcurrentHashMap+链表。
- 内存溢出：大对象缓存怎么处理？→ 容量限制改成内存大小限制，软引用。
- 缓存击穿：热点 key 被淘汰怎么办？→ 热点数据永久不淘汰，或者互斥重建。

### 场景 3：接口限流场景
#### 业务背景
接口防刷、流量削峰、服务降级；限制单位时间内的请求数量，保护服务不被打垮。

#### 算法抽象
在时间窗口内控制请求次数，或者控制请求处理速率。

#### 常见方案对比
| 方案           | 核心原理                         | 优点                   | 缺点                       |
| -------------- | -------------------------------- | ---------------------- | -------------------------- |
| 固定窗口计数器 | 单位时间计数，超了就拒绝         | 实现简单               | 边界临界问题，窗口切换突刺 |
| 滑动窗口       | 细粒度时间分片，滑动计数         | 精确，无临界突刺       | 实现复杂，存储稍大         |
| 漏桶           | 固定速率处理请求，桶缓存请求     | 平滑流量，削峰填谷     | 突发流量不能快速响应       |
| 令牌桶         | 固定速率生成令牌，请求拿令牌执行 | 支持突发流量，平滑处理 | 实现稍复杂                 |

#### 面试答题思路
> 先澄清：限流精度要求？支持突发流量还是要平滑处理？分布式还是单节点？
1. 简单限流用固定窗口就行，实现最简单，但是窗口切换的时候可能有两倍流量的临界问题，对精度要求不高可以用。
2. 要精确限流就用滑动窗口，把时间拆成小格，滑动计算，没有临界突刺，精度高。
3. 如果是流量削峰场景，用令牌桶，匀速生成令牌，支持一定的突发流量，是接口限流最常用的方案。
4. 分布式限流就用 Redis+Lua 脚本，原子执行限流逻辑，保证多节点一致。

#### 避坑与追问点
- 分布式一致性：多节点限流怎么保证准确？→ 中心式限流，或者 Redis Lua 原子操作。
- 限流降级：限流之后怎么处理？→ 返回 429，带 Retry-After 头，或者走降级逻辑。
- 热点限流：针对某个用户/IP 限流，还是全局限流？→ 按维度限流，细粒度控制。

### 场景 4：区间合并与日程调度场景
#### 业务背景
日程安排、会议室预订、区间合并、时间段冲突检测；多个区间，判断冲突、合并重叠区间。

#### 算法抽象
给定一组区间，合并重叠区间，或者判断是否存在重叠区间。

#### 常见方案对比
| 方案           | 时间复杂度 | 核心思路                       | 适用场景                     |
| -------------- | ---------- | ------------------------------ | ---------------------------- |
| 排序后遍历合并 | O(nlogn)   | 按起点排序，遍历合并重叠       | 批量合并区间，离线处理       |
| 差分法         | O(n + max) | 起点+1终点-1，前缀和计算重叠数 | 数值范围小，快速统计重叠次数 |
| 扫描线算法     | O(nlogn)   | 区间端点排序，扫描计数         | 多区间重叠数、最大并发数     |

#### 面试答题思路
> 先澄清：区间数量大概多少？区间范围有多大？是合并还是判断冲突？
1. 常规区间合并，先按区间左端点排序，然后遍历，当前区间和结果最后一个比较，重叠就合并，不重叠就加入结果，时间 O(nlogn)，是最通用的方案。
2. 如果是判断区间冲突，或者求最大重叠数，用扫描线算法，把所有起点终点排序，遇到起点计数+1，终点计数-1，过程中最大值就是最大重叠数。
3. 如果是日程调度、会议室预订这类场景，本质就是区间冲突检测，排序后遍历检查相邻区间是否重叠就行。

#### 避坑与追问点
- 区间开闭：开区间闭区间有没有影响？→ 端点相等算不算重叠，确认业务规则。
- 动态插入：如果区间是动态插入的怎么办？→ 用 TreeMap 维护有序区间，O(logn) 插入查询。
- 跨天区间：时间段跨天怎么处理？→ 拆分区间，或者模运算。

### 场景 5：海量数据判重/去重场景
#### 业务背景
用户手机号去重、URL 判重、垃圾内容过滤；海量数据判断是否存在过。

#### 算法抽象
给定大量元素，判断元素是否已经存在，支持插入和查询，尽量省空间。

#### 常见方案对比
| 方案       | 空间复杂度 | 误判率                                           | 适用场景                           |
| ---------- | ---------- | ------------------------------------------------ | ---------------------------------- |
| HashSet    | O(n)       | 0                                                | 小数据量、精确判重                 |
| 布隆过滤器 | O(k)       | 有一定误判率，不存在的一定不存在，存在的可能误判 | 大数据量、去重、拦截场景，允许误判 |
| 位图       | O(max/8)   | 0                                                | 数值范围不大，整数 ID 判重         |

#### 面试答题思路
> 先澄清：数据量多大？允许误判吗？元素是什么类型？范围多大？
1. 百万级以内，直接用 HashSet 就行，精确判重，实现简单。
2. 亿级海量数据，允许少量误判的话，用布隆过滤器，多个哈希函数映射到位数组，空间特别小，适合大数据去重、黑名单拦截；不存在的一定不存在，存在的有小概率误判。
3. 如果是整数 ID，且范围可控，直接用位图，一个位代表一个 ID，空间最省。
4. 工程落地的话，Redis 有布隆过滤器插件，也有位图数据结构，分布式场景直接用。

#### 避坑与追问点
- 误判率：布隆过滤器误判率怎么控制？→ 调整哈希函数个数和位数组大小。
- 删除支持：布隆过滤器能删除吗？→ 标准布隆不支持删除，要用计数布隆。
- 热点倾斜：大量数据集中在某个区间怎么办？→ 分桶布隆，或者分层判重。

### 题 1：二叉树中的最大路径和
#### 题目描述
LeetCode 124. 二叉树中的最大路径和（困难）
二叉树中的路径被定义为一条从任意节点出发，沿父节点-子节点连接，到达任意节点的序列。路径至少包含一个节点，且不一定经过根节点。
给定二叉树的根节点，返回其最大路径和。

#### 核心思路
1. 路径的本质：任意两个节点之间的通路，可以拆分为「左子树路径 + 根节点 + 右子树路径」。
2. 后序遍历：先算左右子树的最大贡献值（只能选左或右一边，因为要向上延伸）。
3. 全局最大：每个节点都可以作为路径的最高点，计算「左贡献 + 根值 + 右贡献」，更新全局最大值。
4. 负数处理：子树贡献为负的话，就取 0，相当于不选这个子树。

**Model**

~~~

/**
 * 二叉树节点
 */
public class TreeNode {
    public int val;
    public TreeNode left;
    public TreeNode right;

    public TreeNode() {}

    public TreeNode(int val) {
        this.val = val;
    }

    public TreeNode(int val, TreeNode left, TreeNode right) {
        this.val = val;
        this.left = left;
        this.right = right;
    }
}
~~~



#### Java 实现
```java
class Solution {
    private int maxSum = Integer.MIN_VALUE;

    public int maxPathSum(TreeNode root) {
        dfs(root);
        return maxSum;
    }

    // 返回以当前节点为起点的单边最大路径和（只能选左或右，用于向上拼接）
    private int dfs(TreeNode node) {
        if (node == null) {
            return 0;
        }

        // 左右子树最大贡献，负数则取0（不选这个分支）
        int left = Math.max(dfs(node.left), 0);
        int right = Math.max(dfs(node.right), 0);

        // 当前节点作为最高点的路径和，更新全局最大
        maxSum = Math.max(maxSum, left + node.val + right);

        // 返回单边最大和，给父节点拼接
        return node.val + Math.max(left, right);
    }
}
```

#### 复杂度分析
- 时间复杂度：O(n)，每个节点遍历一次。
- 空间复杂度：O(h)，h 为树的高度，递归栈空间；最坏情况 O(n)（链状树）。

#### 面试八股
> 「这道题用后序遍历求解。因为路径可以是任意节点为最高点的左右子树拼接，所以我们递归计算每个节点的单边最大贡献，也就是只能选左或者右分支向上延伸的最大值；同时在每个节点计算左右贡献加当前值的总和，这就是以当前节点为最高点的路径和，更新全局最大值。子树贡献为负的话就取 0，相当于不选这个分支。时间复杂度 O(n)，每个节点走一次，空间是递归栈的高度。」
- 考点：后序遍历、全局最大值维护、负数边界处理。
- 常见追问：如果路径必须从叶子到叶子怎么办？→ 逻辑类似，只是必须选左右两边，不能取 0。

### 题 2：二叉树的最近公共祖先
#### 题目描述
LeetCode 236. 二叉树的最近公共祖先（中等）
给定一个二叉树，找到该树中两个指定节点的最近公共祖先（LCA）。
公共祖先定义：对于节点 p、q，最近公共祖先满足本身是 p、q 的祖先，且深度尽可能深。

#### 核心思路
1. 递归定义：如果当前节点是 p 或 q，或者空，直接返回当前节点。
2. 左右递归：分别找左右子树的 LCA。
3. 结果判断：
   - 左右都不为空：说明 p、q 分在两边，当前节点就是 LCA。
   - 左空右不空：说明都在右边，返回右结果。
   - 右空左不空：说明都在左边，返回左结果。

#### Java 实现
```java
class Solution {
    public TreeNode lowestCommonAncestor(TreeNode root, TreeNode p, TreeNode q) {
        // 终止条件：空节点，或者当前节点就是p/q
        if (root == null || root == p || root == q) {
            return root;
        }

        TreeNode left = lowestCommonAncestor(root.left, p, q);
        TreeNode right = lowestCommonAncestor(root.right, p, q);

        // 左右都有，当前就是祖先
        if (left != null && right != null) {
            return root;
        }
        // 哪边有就返回哪边
        return left != null ? left : right;
    }
}
```

#### 复杂度分析
- 时间复杂度：O(n)，最坏遍历所有节点。
- 空间复杂度：O(h)，递归栈高度。

#### 面试八股
> 「这道题用递归后序遍历。递归函数的定义是返回当前子树中 p 和 q 的最近公共祖先，如果当前节点是空或者 p/q 本身，直接返回。然后分别递归左右子树，如果左右结果都不为空，说明 p 和 q 分别在左右子树，当前节点就是最近公共祖先；如果只有一边有结果，说明两个节点都在那一边，返回那个结果就行。」
- 考点：递归回溯、二叉树后序、公共祖先定义。
- 常见追问：如果是二叉搜索树怎么优化？→ 利用 BST 性质，比较值的大小决定往左还是往右，不用遍历全树。
- 工程延伸：多叉树怎么找 LCA？→ 欧拉序+RMQ，或者倍增法。

### 题 3：最长递增子序列
#### 题目描述
LeetCode 300. 最长递增子序列（中等）
给你一个整数数组 nums，找到其中最长严格递增子序列的长度。
子序列是可以由数组删除某些元素而不改变剩余元素顺序形成的序列。

#### 核心思路
1. DP 定义：`dp[i]` 表示以第 i 个元素结尾的最长递增子序列长度。
2. 转移方程：`dp[i] = max(dp[j] + 1)`，其中 j < i 且 nums[j] < nums[i]。
3. 初始值：每个 dp[i] 至少是 1（自己）。
4. 结果：dp 数组的最大值。

> 进阶优化：贪心+二分，O(nlogn)，维护一个长度为 len 的最小末尾数组。

#### Java 实现（DP 基础版）
```java
class Solution {
    public int lengthOfLIS(int[] nums) {
        if (nums == null || nums.length == 0) {
            return 0;
        }
        int n = nums.length;
        int[] dp = new int[n];
        int maxLen = 1;

        for (int i = 0; i < n; i++) {
            dp[i] = 1;
            for (int j = 0; j < i; j++) {
                if (nums[j] < nums[i]) {
                    dp[i] = Math.max(dp[i], dp[j] + 1);
                }
            }
            maxLen = Math.max(maxLen, dp[i]);
        }
        return maxLen;
    }
}
```

#### 复杂度分析
- 时间复杂度：O(n²)，双重循环。
- 空间复杂度：O(n)，dp 数组。

#### 面试八股
> 「这道题是动态规划的经典子序列问题。dp[i] 定义为以第 i 个元素结尾的最长递增子序列长度，初始值都是 1。然后对于每个 i，遍历前面所有 j，如果 nums[j] 小于 nums[i]，就可以接在 j 后面，dp[i] 取最大的 dp[j]+1。最后 dp 数组的最大值就是答案。时间复杂度 O(n²)。如果数据量大还可以用贪心加二分优化到 O(nlogn)，维护一个每个长度下最小的末尾元素，新来的元素二分找位置替换。」
- 考点：DP 定义、转移方程、子序列和子串的区别。
- 常见追问：O(nlogn) 优化思路？最长连续递增子序列？→ 滑动窗口，一次遍历。

### 题 4：零钱兑换
#### 题目描述
LeetCode 322. 零钱兑换（中等）
给你一个整数数组 coins，表示不同面额的硬币；以及一个整数 amount，表示总金额。
计算并返回可以凑成总金额所需的最少的硬币个数。如果没有任何一种硬币组合能凑出，返回 -1。

#### 核心思路
1. 完全背包问题：每种硬币可以用无限次，求凑成金额的最少物品数。
2. DP 定义：`dp[i]` 表示凑齐金额 i 需要的最少硬币数。
3. 转移方程：`dp[i] = min(dp[i], dp[i - coin] + 1)`，遍历每种硬币。
4. 初始值：dp[0] = 0，其他初始为一个大数（表示不可达）。
5. 结果：dp[amount] 如果还是大数返回 -1，否则返回 dp[amount]。

#### Java 实现
```java
class Solution {
    public int coinChange(int[] coins, int amount) {
        if (amount == 0) {
            return 0;
        }
        int[] dp = new int[amount + 1];
        // 初始化为不可能的大值
        int max = amount + 1;
        Arrays.fill(dp, max);
        dp[0] = 0;

        for (int i = 1; i <= amount; i++) {
            for (int coin : coins) {
                if (coin <= i) {
                    dp[i] = Math.min(dp[i], dp[i - coin] + 1);
                }
            }
        }
        return dp[amount] > amount ? -1 : dp[amount];
    }
}
```

#### 复杂度分析
- 时间复杂度：O(amount × k)，k 是硬币种类数。
- 空间复杂度：O(amount)。

#### 面试八股
> 「这是一道完全背包问题。dp[i] 表示凑齐金额 i 需要的最少硬币数，初始 dp[0] 是 0，其他都设成最大值。然后遍历每个金额，对于每种硬币，如果面额小于当前金额，就可以用这个硬币，dp[i] 取原来的值和 dp[i-coin]+1 的最小值。最后如果 dp[amount] 还是大于 amount 就说明凑不出来返回 -1，否则返回 dp[amount]。」
- 考点：完全背包模型、DP 定义、初始值设置。
- 常见追问：硬币有数量限制怎么办？→ 01 背包，多重背包。
- 边界坑：amount 为 0、硬币面额大于 amount、无解情况。

### 题 5：打家劫舍 III（树型 DP）
#### 题目描述
LeetCode 337. 打家劫舍 III（中等）
小偷发现了一个新的可盗窃区域，这个区域的房屋组成一棵二叉树，相邻的房屋不能同时盗窃，求能盗窃的最大金额。

#### 核心思路
1. 树型 DP，每个节点两个状态：偷、不偷。
2. 后序遍历：先算左右子树的两个状态。
3. 转移：
   - 当前偷：左右子树都不能偷 → `当前值 + 左不偷 + 右不偷`
   - 当前不偷：左右子树可偷可不偷，取最大值 → `max(左偷,左不偷) + max(右偷,右不偷)`
4. 结果：根节点偷和不偷的最大值。

#### Java 实现
```java
class Solution {
    public int rob(TreeNode root) {
        int[] res = dfs(root);
        return Math.max(res[0], res[1]);
    }

    // 返回数组：[0]不偷当前节点的最大金额，[1]偷当前节点的最大金额
    private int[] dfs(TreeNode node) {
        if (node == null) {
            return new int[]{0, 0};
        }

        int[] left = dfs(node.left);
        int[] right = dfs(node.right);

        // 偷当前：左右都不能偷
        int steal = node.val + left[0] + right[0];
        // 不偷当前：左右各自选最大
        int notSteal = Math.max(left[0], left[1]) + Math.max(right[0], right[1]);

        return new int[]{notSteal, steal};
    }
}
```

#### 复杂度分析
- 时间复杂度：O(n)，每个节点遍历一次。
- 空间复杂度：O(h)，递归栈。

#### 面试八股
> 「这是典型的树型动态规划，每个节点有两个状态：偷和不偷。后序遍历左右子树，每个节点都返回两个状态的最大值。如果偷当前节点，左右子树都不能偷，加上左右不偷的值；如果不偷当前节点，左右子树都可以选偷或者不偷，各自取最大值相加。最后根节点两个状态的最大值就是答案。时间复杂度 O(n)，每个节点处理一次。」
- 考点：树型 DP、状态定义、后序遍历。
- 常见追问：如果是多叉树怎么办？→ 逻辑一样，遍历所有子节点。
- 延伸：打家劫舍 I 是数组 DP，II 是环形数组，III 是树，是一套递进的问题。

## 题1：二叉树中的最大路径和

### 实现类 MaxPathSum.java

```
package com.zl.d11.leetcode.group1;

import com.zl.d11.leetcode.model.TreeNode;

/**
 * LeetCode 124. 二叉树中的最大路径和
 */
public class MaxPathSum {
    private int maxSum;

    public int maxPathSum(TreeNode root) {
        maxSum = Integer.MIN_VALUE;
        dfs(root);
        return maxSum;
    }

    /**
     * 返回以当前节点为起点的单边最大路径和（只能选左或右分支，用于向上拼接）
     */
    private int dfs(TreeNode node) {
        if (node == null) {
            return 0;
        }

        // 子树贡献为负则舍弃，取0
        int leftGain = Math.max(dfs(node.left), 0);
        int rightGain = Math.max(dfs(node.right), 0);

        // 当前节点作为最高点的路径和，更新全局最大值
        maxSum = Math.max(maxSum, node.val + leftGain + rightGain);

        // 返回单边最大和
        return node.val + Math.max(leftGain, rightGain);
    }
}
```

## 题2：二叉树的最近公共祖先

### 实现类 LowestCommonAncestor.java

```
package com.zl.d11.leetcode.group1;

import com.zl.d11.leetcode.model.TreeNode;

/**
 * LeetCode 236. 二叉树的最近公共祖先
 */
public class LowestCommonAncestor {

    public TreeNode lowestCommonAncestor(TreeNode root, TreeNode p, TreeNode q) {
        // 终止条件：空节点，或当前节点就是p/q
        if (root == null || root == p || root == q) {
            return root;
        }

        TreeNode left = lowestCommonAncestor(root.left, p, q);
        TreeNode right = lowestCommonAncestor(root.right, p, q);

        // 左右都不为空，当前节点就是公共祖先
        if (left != null && right != null) {
            return root;
        }
        // 哪边有结果返回哪边
        return left != null ? left : right;
    }
}
```

### 实现类 LongestIncreasingSubsequence.java

```
package com.zl.d11.leetcode.group1;

/**
 * LeetCode 300. 最长递增子序列
 */
public class LongestIncreasingSubsequence {

    public int lengthOfLIS(int[] nums) {
        if (nums == null || nums.length == 0) {
            return 0;
        }

        int n = nums.length;
        int[] dp = new int[n];
        int maxLen = 1;

        for (int i = 0; i < n; i++) {
            dp[i] = 1; // 每个元素自身长度为1
            for (int j = 0; j < i; j++) {
                if (nums[j] < nums[i]) {
                    dp[i] = Math.max(dp[i], dp[j] + 1);
                }
            }
            maxLen = Math.max(maxLen, dp[i]);
        }
        return maxLen;
    }
}
```

## 题5：打家劫舍 III

### 实现类 HouseRobberIII.java

```
package com.zl.d11.leetcode.group1;

import com.zl.d11.leetcode.model.TreeNode;

/**
 * LeetCode 337. 打家劫舍 III
 */
public class HouseRobberIII {

    public int rob(TreeNode root) {
        int[] res = dfs(root);
        return Math.max(res[0], res[1]);
    }

    /**
     * 返回数组：[0]不偷当前节点的最大金额，[1]偷当前节点的最大金额
     */
    private int[] dfs(TreeNode node) {
        if (node == null) {
            return new int[]{0, 0};
        }

        int[] left = dfs(node.left);
        int[] right = dfs(node.right);

        // 偷当前：左右子树都不能偷
        int steal = node.val + left[0] + right[0];
        // 不偷当前：左右子树各自选最优
        int notSteal = Math.max(left[0], left[1]) + Math.max(right[0], right[1]);

        return new int[]{notSteal, steal};
    }
}
```
