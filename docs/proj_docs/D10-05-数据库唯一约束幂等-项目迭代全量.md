# D10-05 数据库唯一约束幂等 · 项目迭代全量信息

> 模块：`D10_idempotency_handwritten_demo`
> 方案：**数据库唯一约束（Unique Constraint）+ 事务性幂等记录**
> 基线：JDK 21、Spring Boot 3.5.x、MyBatis-Plus 3.5.17、MySQL（本地学习库）
> 文档定位：记录本次迭代「做了什么、改了哪些文件、如何构建运行、验证结果如何」。

---

## 1. 本次迭代目标

在 `M1-Java\D10` 聚合工程下新增独立模块 `D10_idempotency_handwritten_demo`，实现一个**幂等的订单创建接口**：

- 接口：`POST /api/orders`
- 核心保证：**同一幂等键（Idempotency-Key）的请求，业务最多执行一次**。
- 与此前 `D10_IARL`（Redis 幂等 + Redis 令牌桶）不同，本模块**不依赖 Redis**，改用：
  - 数据库表上的**唯一约束**作为并发抢占的最终裁决；
  - **业务数据与幂等记录在同一数据库事务中提交/回滚**，保证二者状态一致。

## 4. 数据库表

### 4.1 幂等记录表 `idempotency_record`

- 唯一约束：`uk_tenant_api_idempotency (tenant_id, api_code, idempotency_key)`
- 关键字段：`request_digest`（请求体 SHA-256）、`status`（PROCESSING/SUCCEEDED/FAILED）、`result_body`（成功响应 JSON）。

### 4.2 订单表 `order_info`

- 字段：`product_id`、`quantity`、`status`、`idempotency_key`，`idx_idempotency_key` 索引。

建表 SQL 已在本地 `ai_db` 库执行，`SHOW TABLES` 确认两张表存在。

## 5. 构建与运行

### 5.1 构建

```powershell
# 在 D10 根目录，仅构建本模块（不触发 D10_IARL）
mvn -pl D10_idempotency_handwritten_demo -am clean package -DskipTests
```

产物：`target\D10_idempotency_handwritten_demo-1.0-SNAPSHOT.jar`

### 5.2 启动 / 停止

```powershell
# 启动（在新窗口运行，标题 D10-IDEMP-APP）
.\bin\start.ps1        # 或双击 bin\start.bat

# 停止
.\bin\stop.ps1         # 或 bin\stop.bat
```

服务端口：**8083**（避开 8080）。

### 5.3 调用示例

```powershell
$body = '{"productId":1001,"quantity":2}'
Invoke-WebRequest -Uri 'http://localhost:8083/api/orders' -Method Post `
  -Headers @{ 'Idempotency-Key' = 'K1' } `
  -ContentType 'application/json' -Body $body
```

## 6. 验证结果（真实执行）

执行 `script/verify_demo.ps1`，结果如下：

| 场景 | 预期 | 实际 | 结果 |
|---|---|---|---|
| 1. 首次请求 K1 | 201，业务执行一次 | `HTTP 201`，orderId=1 | 通过 |
| 2. 相同参数重复 K1 | 200，返回原结果 | `HTTP 200`，orderId=1 | 通过 |
| 3. 20 线程并发 CK1 | 最多 1 个进入业务 | 201×1，200×18，409×1 | 通过 |
| 4. 不同参数复用 K1 | 409 | `HTTP 409`，code=40901 | 通过 |
| 5. 新键 K2 | 201 | `HTTP 201`，orderId=3 | 通过 |
| 6. 缺少幂等键 | 400 | `HTTP 400`，code=40001 | 通过 |
| 7. 参数校验失败 | 400 | `HTTP 400`，code=40002 | 通过 |
| 8. 租户 T1 使用 K1 | 201，独立作用域 | `HTTP 201`，orderId=4 | 通过 |

**数据库核验（`ai_db`）：**

- `order_info` 共 **4** 条：K1（default）、CK1（仅 1 条）、K2、K1（T1）。
- `idempotency_record` 共 **4** 条，状态均为 `SUCCEEDED`。
- 关键结论：**20 线程并发使用 CK1，订单表仅生成 1 条订单**。

> 场景 3 中出现 1 个 `409`：某请求在胜出请求尚未提交（记录仍为 PROCESSING）时到达，接口返回"请求正在处理中"，属正确的并发保护行为。

## 7. 迭代中踩过的坑（已修复）

1. **PowerShell 启动脚本 `-f` 误解析**：`-ArgumentList '/c', '...' -f $a,$b,$c` 中 `-f` 被当作 Start-Process 参数。修复为预先用独立表达式计算命令字符串。
2. **Logback 滚动策略错误**：`TimeBasedRollingPolicy` 不支持文件名中的 `%i`。修复为 `SizeAndTimeBasedRollingPolicy`。
3. **mysql 客户端短参数被错误解析**：`-h127.0.0.1` 在 PowerShell 中被解析成 host=127。修复为 `--host=127.0.0.1` 长形式，并通过管道传入 SQL。

## 8. 边界与说明

- 本模块数据源为**本地学习库**，使用弱口令仅用于本地演示，**不代表生产可用配置**。
- `FAILED` 状态允许同一幂等键重试；并发重试 FAILED 属于极端边缘场景，本演示未加额外锁。
- 本模块不包含限流（限流在 `D10_IARL` 中演示）。
