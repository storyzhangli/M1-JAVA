## A. JVM 参数配置与启动脚本

### 1. JDK21 标准化参数设计（按功能分组）

>
> 基线：JDK 21 默认 GC 为 ZGC 分代回收器，所有参数对齐JDK 21 官方规范，淘汰JDK8废弃参数。

#### （1）堆内存与空间配置

```
-Xms2g
-Xmx2g
-XX:MaxMetaspaceSize=512m
```

- `-Xms2g`：初始堆内存2GB，与最大值保持一致，**避免运行时堆扩容带来的性能抖动**，生产环境强制要求。
- `-Xmx2g`：最大堆内存2GB，根据服务器资源与业务量级调整，建议预留30%以上的系统内存。
- `-XX:MaxMetaspaceSize=512m`：限制元空间最大512MB；JDK8+元空间位于本地内存，不受堆大小限制，不设置会存在内存泄漏风险。

#### （2）GC 回收器配置

```
-XX:+UseZGC
-XX:+ZGenerational
```

- `-XX:+UseZGC`：显式启用 ZGC 低延迟垃圾回收器；JDK21 默认即为ZGC，显式声明保证环境一致性。
- `-XX:+ZGenerational`：启用分代ZGC（JDK21 默认开启），优化年轻代回收效率，相比旧版ZGC降低CPU开销。> 
> 面试考点：ZGC 停顿时间目标为亚毫秒级，支持TB级堆内存，是大内存、低延迟场景的首选回收器。

#### （3）GC 日志配置（JDK9+ 统一日志框架）

```
-Xlog:gc*,gc+age=trace,gc+ergo=info:file=logs/gc.log:time,uptime,level,tags:filecount=10,filesize=100M
```

- 作用：输出GC详细日志到 `logs/gc.log`，包含GC原因、分代年龄、停顿时间等信息；采用滚动策略，最多保留10个文件，每个100MB。
- 关键说明：JDK9 起废弃 `-XX:+PrintGCDetails` 等旧参数，统一使用 `-Xlog` 语法，这是JDK8→21的高频坑点。

#### （4）故障排查与诊断参数

```
-XX:+HeapDumpOnOutOfMemoryError
-XX:HeapDumpPath=logs/heapdump.hprof
-XX:+PrintCommandLineFlags
-XX:+PrintFlagsFinal
-Dfile.encoding=UTF-8
```

- `-XX:+HeapDumpOnOutOfMemoryError`：OOM时自动生成堆转储文件，是定位内存泄漏的核心手段。
- `-XX:HeapDumpPath=logs/heapdump.hprof`：指定堆转储文件输出路径。
- `-XX:+PrintCommandLineFlags`：启动时打印实际生效的JVM参数，用于验证配置是否生效。
- `-XX:+PrintFlagsFinal`：打印所有JVM参数最终值，用于排查参数覆盖问题。
- `-Dfile.encoding=UTF-8`：强制文件编码为UTF-8，解决Windows环境日志乱码问题。

### 2. 可执行启动脚本

#### （1）Linux 生产环境启动脚本 `bin/start.sh`

```
#!/bin/bash
# 项目根目录
APP_HOME=$(cd "$(dirname "$0")/.." && pwd)
JAR_FILE="$APP_HOME/target/your-project-name.jar"
LOG_DIR="$APP_HOME/logs"

# 创建日志目录
mkdir -p "$LOG_DIR"

# JVM 核心参数
JVM_OPTS="
  -Xms2g
  -Xmx2g
  -XX:MaxMetaspaceSize=512m
  -XX:+UseZGC
  -XX:+ZGenerational
  -Xlog:gc*,gc+age=trace,gc+ergo=info:file=$LOG_DIR/gc.log:time,uptime,level,tags:filecount=10,filesize=100M
  -XX:+HeapDumpOnOutOfMemoryError
  -XX:HeapDumpPath=$LOG_DIR/heapdump.hprof
  -XX:+PrintCommandLineFlags
  -Dfile.encoding=UTF-8
  -Dspring.profiles.active=prod
"

# 后台启动，输出pid
nohup java $JVM_OPTS -jar "$JAR_FILE" > "$LOG_DIR/startup.log" 2>&1 &
echo $! > "$LOG_DIR/app.pid"
echo "应用启动成功，PID: $(cat $LOG_DIR/app.pid)"
echo "启动日志: $LOG_DIR/startup.log"
echo "GC日志: $LOG_DIR/gc.log"
```

>
> 使用方式：`chmod +x bin/start.sh && ./bin/start.sh`

#### （2）Windows 开发环境启动脚本 `bin/start.bat`

```
@echo off

```

## B. 日志链路追踪配置（MDC + TraceId）

>
> 核心目标：一次请求全链路唯一标识，同步/异步线程上下文正确传递，线程池复用不串号；日志可通过traceId聚合。

### 1. 核心实现代码

#### （1）请求入口 TraceId 过滤器

>
> 职责：请求进入时生成/透传traceId，存入MDC；请求结束时清理上下文，避免线程池复用串号。
> 包名说明：SpringBoot3 基于Jakarta EE，所有Servlet API使用`jakarta.*`包，替代旧版`javax.*`。

```
package com.example.demo.filter;

import jakarta.servlet.FilterChain;
import jakarta.servlet.ServletException;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import org.slf4j.MDC;
import org.springframework.core.Ordered;
import org.springframework.core.annotation.Order;
import org.springframework.stereotype.Component;
import org.springframework.web.filter.OncePerRequestFilter;

import java.util.UUID;

/**
 * 全链路TraceId过滤器
 * 优先从请求头X-Trace-Id透传上游traceId，不存在则生成新的traceId
 */
@Component
@Order(Ordered.HIGHEST_PRECEDENCE)
public class TraceIdFilter extends OncePerRequestFilter {

    private static final String TRACE_ID_HEADER = "X-Trace-Id";
    public static final String TRACE_ID_KEY = "traceId";

    @Override
    protected void doFilterInternal(HttpServletRequest request,
                                    HttpServletResponse response,
                                    FilterChain filterChain) throws ServletException, java.io.IOException {
        try {
            // 优先透传上游traceId，没有则生成
            String traceId = request.getHeader(TRACE_ID_HEADER);
            if (traceId == null || traceId.isBlank()) {
                traceId = UUID.randomUUID().toString().replace("-", "");
            }
            MDC.put(TRACE_ID_KEY, traceId);
            // 响应头返回traceId，方便前端排查
            response.setHeader(TRACE_ID_HEADER, traceId);
            
            filterChain.doFilter(request, response);
        } finally {
            // 请求结束必须清理MDC，防止Tomcat线程池复用导致串号
            MDC.remove(TRACE_ID_KEY);
        }
    }
}
```

#### （2）异步线程MDC上下文传递配置

>
> 解决问题：@Async异步、自定义线程池场景下，子线程默认无法继承MDC上下文，导致traceId丢失；线程池复用会出现traceId串号。
> 实现方案：自定义TaskDecorator，父线程提交任务时复制MDC上下文，子线程执行前设置，执行后清理。

```
package com.example.demo.config;

import org.slf4j.MDC;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.core.task.TaskDecorator;
import org.springframework.scheduling.annotation.EnableAsync;
import org.springframework.scheduling.concurrent.ThreadPoolTaskExecutor;

import java.util.Map;
import java.util.concurrent.Executor;
import java.util.concurrent.ThreadPoolExecutor;

/**
 * 异步线程池配置，集成MDC上下文传递
 */
@Configuration
@EnableAsync
public class AsyncThreadPoolConfig {

    @Bean(name = "asyncExecutor")
    public Executor asyncExecutor() {
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        executor.setCorePoolSize(8);
        executor.setMaxPoolSize(16);
        executor.setQueueCapacity(200);
        executor.setKeepAliveSeconds(60);
        executor.setThreadNamePrefix("async-task-");
        
        // 核心：设置MDC上下文装饰器
        executor.setTaskDecorator(new MdcTaskDecorator());
        
        // 拒绝策略：调用方执行，保证任务不丢失
        executor.setRejectedExecutionHandler(new ThreadPoolExecutor.CallerRunsPolicy());
        executor.initialize();
        return executor;
    }

    /**
     * MDC上下文传递装饰器
     */
    static class MdcTaskDecorator implements TaskDecorator {
        @Override
        public Runnable decorate(Runnable runnable) {
            // 父线程：获取当前MDC上下文
            Map<String, String> contextMap = MDC.getCopyOfContextMap();
            
            return () -> {
                try {
                    // 子线程：执行前设置MDC
                    if (contextMap != null) {
                        MDC.setContextMap(contextMap);
                    }
                    runnable.run();
                } finally {
                    // 子线程：执行后清理MDC，防止线程池复用串号
                    MDC.clear();
                }
            };
        }
    }
}
```

>
> 使用方式：异步方法上标注 `@Async("asyncExecutor")` 即可自动继承traceId。

### 2. 日志框架配置（logback-spring.xml）

>
> SpringBoot3 默认日志实现为Logback，配置文件优先级最高；在日志格式中注入traceId变量。

```
<?xml version="1.0" encoding="UTF-8"?>
<configuration scan="true" scanPeriod="30 seconds">
    <!-- 定义日志存储路径 -->
    <property name="LOG_PATH" value="${LOG_PATH:-./logs}"/>
    <property name="APP_NAME" value="demo-app"/>

    <!-- 控制台输出格式：包含traceId -->
    <appender name="CONSOLE" class="ch.qos.logback.core.ConsoleAppender">
        <encoder>
            <pattern>%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] [%X{traceId:-}] %-5level %logger{36} - %msg%n</pattern>
            <charset>UTF-8</charset>
        </encoder>
    </appender>

    <!-- 文件滚动输出 -->
    <appender name="FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
        <file>${LOG_PATH}/${APP_NAME}.log</file>
        <rollingPolicy class="ch.qos.logback.core.rolling.SizeAndTimeBasedRollingPolicy">
            <fileNamePattern>${LOG_PATH}/${APP_NAME}.%d{yyyy-MM-dd}.%i.log</fileNamePattern>
            <maxFileSize>100MB</maxFileSize>
            <maxHistory>30</maxHistory>
            <totalSizeCap>3GB</totalSizeCap>
        </rollingPolicy>
        <encoder>
            <pattern>%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] [%X{traceId:-}] %-5level %logger{36} - %msg%n</pattern>
            <charset>UTF-8</charset>
        </encoder>
    </appender>

    <!-- 日志级别 -->
    <root level="INFO">
        <appender-ref ref="CONSOLE"/>
        <appender-ref ref="FILE"/>
    </root>
</configuration>
```

- 核心格式符：`%X{traceId:-}` 读取MDC中的traceId，不存在时显示`-`占位。

### 3. 链路验证标准

1. **同步请求验证**：调用任意接口，查看控制台日志，Controller层、Service层的日志均携带相同的traceId。
示例日志：```
2026-10-21 10:00:00.123 [http-nio-8080-exec-1] [abc123def456] INFO  c.e.d.controller.UserController - 查询用户信息
2026-10-21 10:00:00.234 [http-nio-8080-exec-1] [abc123def456] INFO  c.e.d.service.UserService - 用户ID:1001 查询完成

2. **异步请求验证**：调用包含@Async方法的接口，异步线程日志与主线程日志traceId一致。
3. **线程池复用验证**：连续多次调用接口，每次traceId唯一，不出现前后请求traceId串用。

### 避坑提示（面试高频）

1. Tomcat线程池是复用的，**过滤器必须在finally中清理MDC**，否则必然出现traceId串号。
2. 异步线程不能只靠InheritableThreadLocal，线程池复用场景下一定会串号，必须用TaskDecorator手动传递+清理。
3. JDK21 GC日志参数不能沿用JDK8的`-XX:+PrintGCDetails`，会出现参数不识别警告。
