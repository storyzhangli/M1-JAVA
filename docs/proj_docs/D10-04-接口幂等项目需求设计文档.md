## 代码练习-接口幂等项目需求设计

**项目名**：`D10_idempotency_handwritten_demo`
**阶段**：第一阶段 · 需求与设计说明

### 一、项目目标

实现一个订单创建接口的幂等控制，模拟客户端重复提交场景，验证相同幂等请求不会重复创建订单，不同参数的相同幂等键会被拒绝。
采用数据库唯一约束+事务性幂等记录的方案，保证业务数据与幂等记录的一致性。

### 二、技术栈

- Java：JDK 21
- 框架：Spring Boot 3.5.16
- 数据库：MySQL 9，使用唯一约束与事务
- 数据访问：MybatisPlus 3.5.17
- 测试：JUnit 5 + Spring Boot Test
- 构建：Maven3.9.16

### 三、接口契约

#### 接口定义

**POST** `/api/orders`

#### 请求头

| 头字段          | 类型   | 必填 | 说明                                 |
| :-------------- | :----- | :--- | :----------------------------------- |
| Idempotency-Key | String | 是   | 客户端生成的唯一幂等标识，长度1~64位 |
| Content-Type    | String | 是   | application/json                     |

#### 请求体

```json
{
  "productId": 1001,
  "quantity": 2
}
```

| 字段      | 类型    | 约束     |
| :-------- | :------ | :------- |
| productId | Long    | 必填，>0 |
| quantity  | Integer | 必填，>0 |

#### 响应约定

##### 1. 首次创建成功（201 Created）

```json
{
  "code": 0,
  "message": "创建成功",
  "data": {
    "orderId": 100001,
    "productId": 1001,
    "quantity": 2,
    "status": "CREATED"
  }
}
```

##### 2. 重复请求，已成功处理（200 OK）

```json
{
  "code": 0,
  "message": "请求已处理",
  "data": {
    "orderId": 100001,
    "productId": 1001,
    "quantity": 2,
    "status": "CREATED"
  }
}
```

##### 3. 相同幂等键，不同请求参数（409 Conflict）

```json
{
  "code": 40901,
  "message": "幂等键冲突，请求参数不一致",
  "data": null
}
```

##### 4. 缺少幂等键（400 Bad Request）

```json
{
  "code": 40001,
  "message": "缺少幂等键",
  "data": null
}
```

##### 5. 参数校验失败（400 Bad Request）

```json
{
  "code": 40002,
  "message": "参数校验失败",
  "data": {
    "productId": "必须大于0"
  }
}
```

### 四、数据模型设计

### 五、核心业务流程

1. 请求到达Controller，校验幂等键存在、格式，校验请求参数。
2. 计算请求体的SHA-256摘要。
3. 开启数据库事务。
4. 尝试插入幂等记录（状态PROCESSING）。
   - 触发唯一键冲突 → 回滚事务 → 查询已有幂等记录。
     - 状态SUCCEEDED → 返回已保存的结果。
     - 状态PROCESSING → 返回「处理中」。
     - 状态FAILED → 重新执行。
5. 插入成功 → 执行业务逻辑，创建订单。
6. 业务成功 → 更新幂等记录为SUCCEEDED，保存响应结果。
7. 提交事务。
8. 异常回滚 → 事务回滚，幂等记录不残留成功状态。

### 六、必须实现的核心规则

1. 缺少`Idempotency-Key`直接返回400错误。
2. 相同租户、相同接口、相同幂等键，不能重复创建订单。
3. 相同幂等键但请求摘要不同，返回409冲突。
4. 幂等记录与订单创建必须在同一个事务中提交/回滚。
5. 唯一键冲突后，必须在新事务中查询已有结果。
6. 并发请求下，数据库唯一约束保证只有一个能成功创建。
7. 幂等记录设置过期时间，定期清理历史数据。

### 七、测试验收要求

#### 基础功能测试

- [ ] 正常请求成功创建订单，幂等记录正确写入。
- [ ] 缺少幂等键返回400。
- [ ] 参数校验失败返回对应错误。
- [ ] 相同键相同请求体重复提交，只创建1条订单，第二次返回已有结果。
- [ ] 相同键不同请求体，返回409冲突。
- [ ] 不同租户相同幂等键，互不影响。

#### 事务与异常测试

- [ ] 订单创建失败时，幂等记录不会显示成功。
- [ ] 事务回滚后，相同幂等键可以重试。
- [ ] 唯一键冲突异常正确识别，不与其他数据库异常混淆。
- [ ] 应用重启后，已提交的幂等结果仍然有效。

#### 并发测试

- 20线程并发提交同一个幂等键+相同请求体。
- 验证：最终只有1条订单记录，1条成功幂等记录；所有响应符合约定。
- 说明数据库唯一约束在并发中的作用。
